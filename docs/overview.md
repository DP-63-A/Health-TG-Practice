### 2.3 Общие правила отображения
- Числа и агрегаты не считаем, округляем только вид. Предложение: ккал, граммы, шаги, уд/мин — до целого; минуты сна — до целой минуты, затем «Х ч Y мин».
- Отсутствие значения показываем как «—», не как 0.
- День без данных — разрыв на графике, не ноль.
- Пустой период (`days_with_any_data = 0`) — сообщение об отсутствии данных, вымышленных показателей нет.
- Подпись «пульс покоя» добавляется только при `qualifier = "resting"`.
- Дневной итог шагов выбран сервером, повторно не суммируем.
- Время `generated_at` показываем в поясе `period.timezone`, не в поясе браузера.


## 3. Периоды

Источник: `contracts/schemas/analytics.json`, `contracts/BE3-01-CONTRACT.md` 

### 3.1 Выбор периода

| Кнопка | `period` в запросе | Локальных дат | Что входит |
|---|---|---|---|
| Сегодня | `today` | 1 | одна дата, `from` = `to` |
| 7 дней | `days_7` | 7 | 7 дат, сегодняшняя включительно |
| 21 день | `days_21` | 21 | 21 дата, сегодняшняя включительно |

- Границы дней считает сервер, `period.from` и `period.to` включительны. Фронтенд даты периода не вычисляет.

- При переключении кнопки выполняется новый запрос, на время ожидания экран в состоянии loading (раздел 6).

- Период при первом открытии: `days_7` 


### 3.2 Число дней с данными
Строка «Дней с данными: N из M».
- N = `observations.days_with_any_data`, M = `observations.days_in_period`. Фронтенд их не считает.
- N — число дней, в которых есть любые данные. Оно может отличаться от `days_with_data` на карточках сна и шагов (там считаются дни только с этой метрикой).
- N меньше M: показываем как есть, дни без данных на графиках не рисуем нулями.
- N = 0: состояние «пусто» (раздел 6).
- Для «Сегодня» (M = 1) строку «N из M» можно заменить на «Данные за сегодня есть / нет» (предложение).

### 3.3 Время актуальности
Строка «Обновлено HH:MM».
- Поле: `observations.generated_at` (обязательное, UTC, окончание `Z`).
- Показывается в часовом поясе `period.timezone`. Пример: `2026-09-19T20:05:00Z`, Europe/Warsaw (UTC+2) → «Обновлено 22:05».


### 3.4 Часовой пояс
- Пояс берётся из данных пользователя (`/me`), передаётся в запрос параметром `timezone` (IANA-имя, например Europe/Warsaw) и возвращается в `period.timezone`.
- Пояс браузера не используется нигде, в том числе как запасной вариант.
- Если `timezone` не передан, сервер использует Europe/Warsaw. Для пользователя в другом поясе это даст «чужие» границы дней, поэтому пояс всегда передаётся явно.
- Пример: пользователь в Варшаве, местное время 00:30 20 сентября (22:30 19 сентября по UTC). «Сегодня» — 20 сентября.

**Предлагаемый формат:**

`/diary?from=YYYY-MM-DD&to=YYYY-MM-DD&type=TYPE`

`/diary?from=2026-09-16&to=2026-09-16&type=meal`
