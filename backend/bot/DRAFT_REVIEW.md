# Проверка текстового черновика

После разбора бот показывает ту же Entry, которую открывает Mini App по `/diary/{id}`.
Кнопки: «Сохранить», «Изменить», «Не сохранять», «Обновить» и «Открыть в Mini App»
(последняя доступна при заданном HTTPS `MINI_APP_URL`). Возврат из ввода поля
сохраняет сам черновик. Обновление перечитывает запись после работы в Mini App.

Числа и даты разбирает `CorrectionInputParser`. Для еды доступны масса и нутриенты;
основа нутриентов сохраняется, автоматического пересчёта порции нет. Для метрик
исправляется значение или календарная дата. Для заметки доступна дата.
Неизвестное значение показывается как неизвестное, а не ноль.

Даты шагов, сна и пульса хранятся в `payload.local_date`: день итога, дата
пробуждения и дата измерения соответственно. `occurred_at` — неизменный момент
исходного сообщения. `local_time` пульса может быть неизвестным; правка даты
его не меняет. Бот и форма вызывают один `EntryCoreService.patch` с владельцем
и ожидаемой ревизией. Для еды остаётся прежняя семантика `occurred_at`;
правка даты сохраняет время в часовом поясе пользователя и отклоняет DST-неоднозначность.

`DraftReviewFlow` хранит выбор поля и намерение операции в `DialogStateService`.
Перед мутацией сохраняется `draft_pending` с исходной ревизией и значением
(число сериализуется десятичной строкой), а для confirm — стабильным submission ID.
Один Telegram update ID записывает состояние только один раз. После мутации
pending остаётся до следующего нового update: второй записи completed тем же ID нет.
Повтор patch разрешён только при исходной ревизии. Изменившаяся запись перечитывается;
совпадение значений не объявляется доказательством успешного повтора.

Поддерживаемая топология — один polling worker одного бота. В одном CoreBotFlow
обработка сообщений и callback сериализована. Атомарная проверка owner/revision
в ядре защищает также от одновременной правки в Mini App. Несколько независимых
polling-процессов для одного токена не поддерживаются. Сбои хранилища передаются
runtime для повтора; ошибка не превращается в подтверждение сохранения.

Аналитика сна берёт последний сообщённый итог за wakeDate; при преобразовании
Entry в аналитическую модель wakeDate берётся из `payload.local_date`. Для пульса
выбирается последняя `local_date` периода, затем последнее сообщение внутри неё.
В результате отдельно передаются `local_date`, `local_time` и `occurred_at`.
API аналитики не реализуется этим сценарием.

Автоматические проверки не заменяют живую проверку Telegram → HTTPS Mini App →
общая MongoDB, авторизацию initData, прямую загрузку SPA-маршрута и возврат к боту.
