# Локальная проверка распознавания еды (#72)

Java 21. Команды выполняются из корня проекта. Demo не запускает Spring, Telegram или БД.

В каждом новом окне Windows PowerShell перед запуском настройте вывод UTF-8:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Это настройка текущего окна. Одного `chcp 65001` может быть недостаточно: PowerShell/.NET может сохранять прежнюю кодировку. Повторное выполнение команды безопасно. После запуска проверьте, что «печёное яблоко 🍎» отображается без искажений; `BUILD SUCCESSFUL` само по себе не подтверждает правильность отображения текста.

```powershell
.\gradlew.bat :backend:bot:recognizeFood --args='fixture backend/bot/examples/synthetic.png'
```

Это **fixture**, заранее записанный ответ «печёное яблоко 🍎», а PNG — синтетический рисунок для проверки чтения файла. Ответ не зависит от рисунка. Такой запуск не доказывает качество модели.

Для настоящего распознавания проверьте, что ключ относится к вашему проекту с бесплатным доступом. В новом окне PowerShell (совместимо с Windows PowerShell 5.1) выполните блок ниже из корня проекта. После приглашения вставьте ключ: ввод скрыт и не записывается как команда в историю. Сам ключ не вставляйте в код, файлы проекта или чат.

```powershell
$recognitionKey = Read-Host 'Введите Gemini API key (скрытый ввод)' -AsSecureString
try {
    [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
    $env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', $recognitionKey).Password
    .\gradlew.bat :backend:bot:recognizeFood --no-daemon --args='live "C:/photos/food.jpg" gemini-3.5-flash-lite'
} finally {
    Remove-Item Env:GEMINI_API_KEY -ErrorAction SilentlyContinue
    $recognitionKey.Dispose()
    Remove-Variable recognitionKey -ErrorAction SilentlyContinue
}
```

Замените `C:/photos/food.jpg` путём к собственному разрешённому учебному фото. Переменная ключа существует только в этом процессе PowerShell и запускаемых им процессах; `finally` удаляет её после завершения, в том числе при ошибке. `--no-daemon` не оставляет этот запуск Gradle работающим между командами. Не выводите переменную ключа и не включайте отладочную печать окружения.

Один запуск делает один запрос. Цена неизвестна и не считается нулевой; приложение не управляет тарифом проекта. Модель задаётся третьим аргументом, по умолчанию `gemini-3.5-flash-lite`. Режим всегда задаётся первым аргументом; автоматической подмены live на fixture нет. Для пути с пробелами сохраните внутренние двойные кавычки. В Linux/macOS используйте `./gradlew` и настройте переменную окружения средствами своей оболочки.

Успех имеет код завершения 0 (в том числе результат с уточнениями), ошибка распознавания — 1, неправильная команда — 2. Автотесты: `./gradlew :backend:bot:test`; им не нужны ключ и сеть модели.

## Что проверяется

До модели проверяются формат JPEG/PNG по содержимому, размер до 5 MiB, заголовок с разрешением до 12 000 000 пикселей и полное декодирование. Время ожидания ответа, включая его загрузку, ограничено 30 секундами; размер ответа — 64 KiB. Повторы только по явному новому запуску пользователя.

`response-schema.json` — единая структура запроса к модели и локальной проверки. Дополнительно проверяются происхождение значений и даты. Имена и единицы пищи взяты из `contracts/schemas/payloads/meal.json`, происхождение — из `contracts/schemas/common.json`. Это частичный результат распознавания, а не Entry: нет owner, revision, статуса хранения. Дополнительные `local_date` и `local_time` сохраняют частичную дату без выдуманного часового пояса. `occurred_at` требует явного смещения UTC. Значения дат представлены проверенными ISO-строками, чтобы сохранить исходное смещение и не подключать сериализацию Java Time только для demo.

Неизвестное остаётся `null`; известный ноль не превращается в неизвестное. `field_origins` содержит только известные поля: `estimated` для предположения или `extracted` для видимого значения. Оценка не становится измерением. Основа питательности сохраняется без пересчётов. `missing_fields` вычисляется программой как список доступных уточнений; он не требует заполнить все нутриенты перед будущим сохранением. Правила подтверждения остаются родительской задачей. Неизвестная полная дата требует уточнения даже при известной частичной дате.

Логи содержат только идентификатор операции, режим, статус, длительность и доступные счётчики токенов. Demo отдельно печатает результат в консоль для личной проверки. Не направляйте этот вывод с личными данными в общие логи. Ключ и исходное изображение не печатаются. Сырой ответ провайдера не сохраняется автоматически.

## Границы проверки

Модель может ошибиться в составе, порции и прочтении надписей: проверка JSON не доказывает фактическую точность. Текст изображения трактуется как данные; инструментов выполнения или сохранения у модели нет. Фото экранов здоровья/часов, В автономном demo Telegram-диалог, хранение и аналитика не реализуются здесь.

Личную live-проверку выполняют отдельно: дата/модель, ID операции и responseId при наличии, обезличенный ответ и результат проверки. Успешный fixture не заменяет эту проверку. Для проверки Unicode ожидайте читаемое «печёное яблоко 🍎» в выводе fixture; Run в IDEA проверяется отдельно от Gradle.

Источники API: [generateContent](https://ai.google.dev/api/generate-content), [структурированный ответ](https://ai.google.dev/gemini-api/docs/structured-output), [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).

## Подключение к Telegram (#9)

Для BotApplication явно задайте `FOOD_RECOGNITION_MODE=fixture` либо `live`.
По умолчанию используется `disabled`: обработка фото выключена. Fixture возвращает учебный
ответ и помечает каждое сообщение режима; изображение в этом режиме не распознаётся.
Для live нужен `GEMINI_API_KEY`. Необязательный `GEMINI_MODEL` по умолчанию равен
`gemini-3.5-flash-lite`. Автоматического повтора модели или перехода в fixture нет.
В IDEA откройте Run → Edit Configurations → BotApplication → Environment variables.
Ключ храните в локальной конфигурации, не включённой в Git, без общего файла запуска.

API и бот должны использовать одну MongoDB и один `FILE_STORAGE_ROOT` (см. документацию
файлового хранилища). Отправьте одно разрешённое учебное изображение JPEG/PNG как фото
или документ: до 5 МиБ и 12 Мп. Альбомы отклоняются. Подпись не передаётся модели и не
заменяет поля результата: исправления вводятся ответами или в общей карточке черновика.
Неизвестные описание, дата и время уточняются до создания Entry. Для неизвестной массы
можно ответить «не знаю». Калории и БЖУ остаются null, пока их не распознали или не ввели
в карточке. Основа per_100g/per_serving/unknown и происхождение estimated/extracted сохраняются;
пересчёт порции в этом обработчике не производится.

Кандидат хранится в DialogState. Кнопки повторного вызова, ручного ввода и отмены содержат
исходный update и текущую revision; старые кнопки не меняют нового кандидата. Для этапов
обработки, результата, файла и Entry используется ограниченный набор фазовых ключей.
После успешной привязки файла состояние передаётся общей карточке по её контракту:
ключ main:update, schema_version, entry_revision и timezone.

После перезапуска или потери ответа модели нужен явный «Повторить»: он может повторить
платный вызов. После ошибки файла/Entry/привязки «Продолжить» восстанавливает операцию с
тем же ключом создания Entry. До сохранения изображения бот записывает reserved_file_id в
DialogState отдельной фазой. Хранилище сначала резервирует этот UUID в MongoDB, затем пишет
файл. Повтор с тем же владельцем и содержимым использует тот же UUID, в том числе после
потери ответа либо перезапуска. Другой владелец или содержимое под тем же UUID отклоняются.
Устранено окно потери ссылки: сбой после записи файла до записи file_id больше не создаёт
новый файл при повторе. Старый вызов store без UUID сохранён для прежних потребителей;
возобновляемый фотодиалог использует новый вызов с заранее записанным UUID.
MongoDB и файловая система не образуют одну атомарную транзакцию: после ошибки диска
резервация может ожидать повтора, а после отмены могут остаться непривязанные данные.
Автоматическая очистка отмены и гарантия единственного вызова модели не заявляются. Entry остаётся
черновиком до существующего общего подтверждения. После привязки Mini App открывает тот
же file_id через защищённый API.

Фото еды имеет source_kind=food_photo и type=meal. Формат результата — RecognitionResult:
масса в граммах, энергия в ккал, нутриенты в граммах; исходная основа расчёта сохраняется.
local_date/local_time — явные календарные значения, occurred_at содержит смещение;
отсутствующие значения неизвестны. Экраны здоровья и часов требуют отдельной схемы и
преобразования и в этот обработчик не входят.

Автотесты и fixture не заменяют ручной live-протокол: фото → уточнение → черновик →
исправление → подтверждение/отмена → та же запись и изображение в Mini App. Используйте
разрешённые учебные изображения; фиксируйте модель, идентификаторы запросов, режим и
результаты без ключей и личного содержимого.

Происхождение собранной даты сохраняется отдельно: две распознанные части дают
occurred_at=extracted; две введённые пользователем — reported; смешанные — computed с
сохранением происхождения каждой части. Новое фото проверяет общий порядок updates перед
загрузкой, а завершение фотодиалога возвращает этот порядок обычному текстовому вводу.
