# Разбор текста (BE2-02, #63)

`TextInputParser.parse(String)` — автономная Java-функция. Она не подключена к обработчику
Telegram, не создаёт запись и не обращается к хранилищу, внешней модели или часам компьютера.
Это реализация части #7, а не всего сценария сохранённого диалога.

## Границы и результат

Ограничение — 2000 Unicode-кодовых точек **исходной** строки (`codePointCount`), до удаления
пробелов. Составной emoji может занимать несколько точек. `null`, пустой или пробельный ввод,
повреждённая UTF-16-строка отклоняются. Исходный текст сохраняется неизменным.

Результаты `PARSED`, `NEEDS_CLARIFICATION`, `NOTE_SUGGESTED`, `REJECTED` относятся к разбору,
а не к `Entry.status`. Результат содержит исходный текст, известные данные и список причин
с кодом и полем. При неоднозначности значение не выбирается; при необходимости уточнить дату
уже надёжно извлечённое число сохраняется. Предложение заметки никогда не сохраняет её.

`ParsedData` — промежуточные данные, не новая серверная `Entry`: `type`, `payload`,
`fieldOrigins`, отдельно явно указанные `date`/`time`. Источник всегда `text`. Поля payload
соответствуют существующим `contracts/schemas/payloads/`. Неизвестные поля отсутствуют.
Неполный результат (например, только `code` без `value`) не является валидным серверным
запросом. `PARSED` также не означает готовности к `createDraft` или подтверждению.
Здесь нет `id`, владельца, `revision`, `occurredAt`. Вопрос заполнения `occurredAt`
остаётся для интеграции родительской задачи.

## Реализуемые правила

Это выбранные правила первого обработчика, **не обязательная грамматика из ТЗ**. Обрабатываем
одно явно описанное событие. Регистр, `ё/е`, повторяющиеся пробелы, мужской/женский род
поддержанных глаголов не меняют смысл. Не требуется шаблон `еда: ...`.

| Вид | Распознаваемые формулировки | Поля |
|---|---|---|
| Сон | «спал/спала», «поспал/поспала», «сон», «продолжительность сна» | `sleep_duration_min`, длительность с явными ч/часами/мин/минутами |
| Шаги | «шаг/шага/шагов/шаги», «нашагал/нашагала», «количество шагов» | `steps`, `count`, целое число |
| Пульс | «пульс», «сердцебиение», «частота сердечных сокращений» | `heart_rate`, единица только при явном `bpm`, `уд/мин`, «ударов в минуту»; контекст только при явном «в покое»/«текущий» |
| Еда | «съел/съела», «поел/поела», «еда:», «на завтрак/обед/ужин была ...» | описание исходными словами; необязательная масса г/гр/грамм/кг/килограмм |

Поддержаны цифры, десятичная запятая/точка, русские количественные целые от нуля до
999 999 (например, «семь», «восемь тысяч», «две тысячи триста»). После десятка допускается
только единица 1–9: «двадцать один» корректно, «двадцать десять» — нет; «сто одиннадцать» корректно. Последовательности
«один два», смешанные «7 тысяч», числовые диапазоны, дроби словами, разделители тысяч,
научная запись не трактуются как надёжное одно число. Слова «минус»/«плюс» поддерживаются.
Один знак может быть отделён пробелом от числа; повторный знак («минус -100», «--100»)
требует уточнения и никогда не превращает отрицательное измерение в положительное.
Тире `–`/`—` непосредственно перед числом неоднозначно (разделитель или минус), поэтому
такое значение также требует уточнения без выбора знака.
В этой грамматике для шагов поддержано целое число (общая схема допускает `number`);
отрицательные шаги, длительность и масса — ошибка. Отрицательная запись пульса требует
уточнения как неподдержанный ввод; медицинские пороги и новый минимум в контракт не вводятся.

Часы переводятся в минуты точно через `BigDecimal`, кг — в г. `fieldOrigins.value`
(`mass_g`) равен `computed` при пересчёте; явно названные данные имеют `reported`.
Калории и другие нутриенты не вычисляются. Числа вне поддержанного выражения не игнорируются:
нужен разбор неоднозначности, а не выбор первого числа.

Явные даты: `ДД.ММ.ГГГГ` и `ГГГГ-ММ-ДД`, время `ЧЧ:ММ`; проверяется существование даты
и диапазон времени. Дата без времени остаётся без времени. «Сегодня», «вчера», названия
дней/месяцев и другие неподдержанные временные обороты требуют уточнения, без подстановки
даты компьютера. Для показателя отсутствие даты требует уточнения; для еды — также,
а отсутствие массы и калорий допустимо. Шаги/сон требуют явного признака дневного итога
(«за день», «за сутки», «суточный/суточная/суточное»). Для сна «проснулся/проснулась»
обозначает дату пробуждения. Иначе длительность сохраняется как известная, но её отношение
к дневному итогу требуется уточнить. Никакой эпизод сна не превращается в итог автоматически.

Желание, условие, вопрос, явное отрицание или другой человек не превращаются в факт
пользователя. Эти фразы предлагаются как заметки, а явные альтернативы/поправки
(«6 или 7», «не 6, а 7»), несколько событий — как необходимость уточнения.
Словарь таких маркеров ограничен: неизвестный сложный текст нельзя считать безопасно
понятым только по одному знакомому слову. У метрик проверяются не только ключ и число,
но и остальные слова; неподдержанный остаток требует уточнения. У еды свободное описание
сохраняется, но дополнительные числа/времена/маркер нескольких приёмов пищи требуют уточнения.
Цитаты требуют уточнения, а не считаются собственным событием. Для еды перед глаголом
приёма пищи допустимы только известные связки («я», «на обед», явная дата/время).
Незнакомое лицо перед глаголом, например «коллега съела», не попадает в описание еды.
Приготовление, заказ или покупка не означают, что еда съедена: «на обед готовлю пасту»
требует уточнения. Без глагола еды поддержано явное описание «на обед была паста»
либо метка «еда: паста»; просто меню/план «на обед паста» требует уточнения.
Масса должна однозначно относиться к одному описанию: «200 г пасты» и «паста 200 г»
поддержаны, а «паста и 200 г супа», «паста и суп 200 г» — уточнение без общей массы.
Составные единицы `г/кг`, `кг/день` не обрезаются до первого `г`/`кг`.
У метрики с непонятным смысловым остатком (например, `пульс 70 кг`) сомнительное число
не выдаётся как надёжный `value`. Известная относительная дата обрабатывается отдельно:
в `вчера за день прошла 8000 шагов` число известно, а дата требует уточнения.

## Примеры для приёмки

| Текст | Результат |
|---|---|
| `Я спала семь часов` | Уточнение даты и дневного итога; известно 420 min |
| `Продолжительность моего сна составила 7 часов` | Тот же результат |
| `25.09.2026 сон за день: 7 ч 10 мин` | Разобрано: 430 min, дата; время неизвестно |
| `За день прошла 8000 шагов` | Уточнение даты; известно 8000 count |
| `24.09.2026 суточное количество шагов составило восемь тысяч` | Разобрано: 8000 count |
| `25.09.2026 в 10:15 пульс в покое 68 уд/мин` | Разобрано: 68 bpm, resting, дата/время |
| `25.09.2026 на обед съела пасту, 200 г` | Разобрано: описание «пасту», масса 200 г |
| `25.09.2026 еда: паста` | Разобрано, без выдуманной массы/калорий |
| `Хочу спать 8 часов`, `Дочь спала 8 часов`, `Не считала шаги` | Предложение заметки, не измерение |
| `Спала нормально` | Предложение заметки, не придуманная длительность |
| `Спала 6 или 7 часов`, `Спала не 6, а 7 часов` | Уточнение без выбранного значения |
| `За день прошла -100 шагов`, `31.02.2026 пульс 70 уд/мин` | Ошибка значения/даты |

Для ручной проверки после `:backend:bot:compileJava` можно запустить `TextParserDemo`
как обычный Java main в IDEA, либо из корня проекта:

```powershell
& "$env:JAVA_HOME/bin/java.exe" -cp backend/bot/build/classes/java/main org.healthtg.bot.text.TextParserDemo
```

Введите сообщение и нажмите Enter; пустая строка завершает демонстрацию. Результат печатается
локально, поэтому используйте вымышленные примеры. Demo не запускает Spring/Telegram.

## Что останется после #63

Расширение грамматики, календарный контекст пользователя, интеграция с диалогом и хранилищем,
подтверждение/исправление, полноценная приёмка #7 — отдельная работа. Обработчик не обещает
понимать любое предложение русского языка. Неизвестный текст сохраняется в результате,
чтобы будущий диалог не терял слова пользователя.
