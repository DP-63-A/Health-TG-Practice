# Backend: Telegram-бот

Модуль `backend` входит в общую Gradle-сборку. Точка входа — `org.healthtg.bot.BotApplication`.

## Стек и возможности

Java 21, Spring Boot 3.5.6, TelegramBots client 9.2.0; используется корневой Gradle Wrapper 8.11.1.
Бот получает сообщения через long polling: публичный сервер для его запуска не нужен. HTTP-сервер, MongoDB, миграции и LLM этот модуль пока не запускает.

Поддерживаются закрытый доступ в личном чате, `/start`, `/state`, постоянная кнопка «Отметить состояние» и отдельное меню Mini App. В явном тестовом режиме `/state` и кнопка открывают категории → оценки 1–5 → результат с отменой. По умолчанию сохранение недоступно.

## Настройки

Настройки читаются из переменных окружения. Файлы `.env` автоматически **не загружаются**.

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен тестового бота от BotFather; обязательно |
| `TELEGRAM_ALLOWED_USER_IDS` | Положительные Telegram ID разрешённых пользователей через запятую; обязательно |
| `MINI_APP_URL` | HTTPS-адрес Mini App без логина и пароля; необязательно для запуска бота |
| `CHECKIN_MODE` | `unavailable` по умолчанию; `fixture` для проверки кнопок с памятью вместо БД |

Имя бота определяется автоматически через `getMe`. При отсутствии адреса Mini App бот сообщает, что кабинет не подключён; проверка его открытия остаётся невыполненной.

Токен и реальные ID задавайте в **локальной** конфигурации запуска IDEA (Run → Edit Configurations → Environment variables). Не включайте сохранение конфигурации в файле проекта и не отправляйте её в Git. Не записывайте секреты непосредственно в команды, исходники, скриншоты и отчёты.

## Проверка без Telegram

Из корня репозитория на Java 21:

```powershell
.\gradlew.bat :backend:test :backend:bootJar
```

Тесты используют синтетические данные и не требуют токена. Для Windows с кириллицей в пути и ошибкой загрузки тестового класса используется проверяемый вариант:

```powershell
.\gradlew.bat '-Dorg.gradle.jvmargs=-Dfile.encoding=COMPAT' :backend:test :backend:bootJar --no-daemon
```

Linux/macOS: `./gradlew :backend:test :backend:bootJar`.

Отчёт тестов: `backend/build/reports/tests/test/index.html`.

## Настоящий запуск

В IDEA откройте корень репозитория, синхронизируйте Gradle, выберите Java 21 для проекта и Gradle. Создайте конфигурацию Application для класса `org.healthtg.bot.BotApplication`, classpath модуля backend и укажите локальные переменные выше. Запустите её.

Из терминала, в котором переменные уже настроены: `./gradlew :backend:bootRun` (Windows: `.\gradlew.bat :backend:bootRun`). Либо запустите собранный `backend/build/libs/backend-0.1.0.jar` через `java -jar`.

Один токен должен обслуживаться только одним запущенным экземпляром. Если для бота установлен webhook, запуск отклоняется: приложение не удаляет его и не очищает очередь сообщений. Остановка — Stop в IDEA или Ctrl+C в терминале.

Не включайте отладочные логи TelegramBots/HTTP-клиента: они могут содержать секретный URL запроса. Штатные сообщения приложения не выводят токены, ID и текст сообщений.

## Ручная приёмка

1. Разрешённый пользователь пишет `/start` в личном чате: учебное предупреждение и постоянная кнопка видны.
2. Без `CHECKIN_MODE=fixture` `/state` и «Отметить состояние» сообщают о недоступном сохранении. С `fixture` проверьте четыре категории, оценки 1–5 и отмену: результат обязательно помечен «Тестовый режим: в БД не сохранено».
3. Пользователь вне списка и групповой чат не получают доступ к функциям.
4. При настроенном реальном HTTPS-адресе кнопка меню открывает Mini App. Тестовый адрес-заглушка эту проверку не заменяет.
5. Остановите приложение: процесс завершается, polling прекращается.

Сетевые ошибки вызывают повтор с задержкой. Ошибки авторизации/конфликт второго polling останавливают обработку. После трёх неудачных попыток доставки одного ответа бот останавливается, не подтверждая последний update. При частично отправленном ответе повтор может повторить его часть. После перезапуска Telegram может повторно прислать неподтверждённые сообщения; дедупликация операций записи относится к будущему ядру.

Автоматические тесты и сборка не заменяют эти ручные проверки с настоящим ботом и кабинетом.

## Проверка диалога BE2-05 без БД

Для самостоятельного запуска добавьте `CHECKIN_MODE=fixture` к локальным настройкам IDEA и перезапустите бот. Используйте только синтетические отметки. Время ответа показано в Europe/Warsaw с UTC-смещением; внутри используется Instant.

Проверьте повтор одной оценки и нажатие другой оценки в той же клавиатуре: новая отметка не создаётся. Начните новый `/state`, затем отмените предыдущую сохранённую отметку: её кнопка отмены остаётся действительной. Повтор отмены безопасен. Старые кнопки незавершённого выбора недействительны. После перезапуска записи потеряны, старые кнопки не обещают сохранения или отмены.

Хранение ограничено 1000 диалогами и 1000 отметками на запуск. При заполнении бот просит перезапуск; ключи не вытесняются, чтобы повторы не превратились в новые записи. Неопределённый результат сохранения блокирует новый выбор до успешного повтора прежнего запроса. В памяти нет настоящего дневника, БД, авторизации API или восстановления данных. `CheckinStore` — локальная граница бота для будущего подключения BE1, не согласованный общий контракт.

Просроченный ответ Telegram на callback (400 для AnswerCallbackQuery) пропускается; сама сохранённая операция не повторяется. Другие ошибки доставки сохраняют существующий ограниченный retry с остановкой. Ошибки хранения и отмены проверяются автоматическими тестами, без настоящего Telegram.
