# BE1-01: проверка контракта

Источник: `student_project_complete_7673.pdf`, ТЗ v1.0 от 16.09.2026, разделы 4–8 и 10; карточка BE1-01. Проверка относится к текущим рабочим файлам до коммита. Реализация API здесь не проверяется.

| Критерий | Проверка | Результат | Статус |
|---|---|---|---|
| AC1 | `gradlew.bat validateContracts :contract-validator:validate --offline --console=plain`; сверка 11 операций `/api/v1` и внутренних методов | OpenAPI и JSON Schema разобраны, ссылки локальных примеров существуют; способ генерации типов с FE1/FE2 ещё не согласован | Частично |
| AC2 | Та же команда; все положительные и отрицательные JSON-fixtures | Положительные проходят, отрицательные отклоняются по ожидаемому полю и ограничению | Пройдено для fixtures |
| AC3 | `entry-draft-meal.json`, `entry-meal.json`, `entry-metrics-zero-steps.json` | Показаны `draft`/`confirmed`, `estimated`/`reported`/`computed`, `null`/`0` | Пройдено для примеров |
| AC4 | `rules/runtime-invariants.md` | Owner, переходы статусов, revision и повторы описаны как runtime-правила, не как доказанная реализация | Пройдено как документация |
| AC5 | `OPEN-DECISIONS.md`, review FE1/FE2/BE2/BE3 | D1–D10 остаются предложениями; подтверждений потребителей нет | Ожидает согласования |
| AC6 | PR с командами, результатом, коммитом и review | Контрактные файлы ещё не отслеживаются Git; PR и проверенного коммита нет | Не выполнено |

Техническая проверка проведена на JDK 21 и Gradle 8.11.1. Она использует только схемы и fixtures, без работающих backend, frontend и хранилища. После согласования открытых решений повторить `validateContracts` и передать контракт потребителям. Итоговое решение о приёмке принимает другой участник.
