# Решения, не зафиксированные в ТЗ

Ниже не новые требования и не утверждённые решения. Это вопросы, которые исполнитель обязан проверить в актуальном контракте/обсуждении и при отсутствии ответа вынести владельцу. Полный объём задач уже описан; недостающие значения не следует молча придумывать.

| Вопрос | Кто согласует | Где закрепить / затронутые задачи |
|---|---|---|
| Имена и вложенность payload/candidate/analytics, точные JSON-примеры | BE1/BE2/BE3 и потребители FE1/FE2 | BE1-01, BE2-03, BE3-01; contracts и fixtures |
| Пагинация, порядок истории, границы from/to, точные параметры периода | BE1/BE3 с FE1/FE2 | BE1-01, BE3-01, FE1-03, FE2-04 |
| Единая политика 403/404, формат auth-response и сессии, синтаксис If-Match | BE1 с FE1/BE2 | BE1-01/02/04, FE1-01/04/05 |
| Повторные cancel/delete и недопустимые переходы статусов | BE1 с BE2/FE1 | BE1-03/04, BE2-06, FE1-04/05 |
| Сигнатуры методов ядра, ключ повтора Telegram update, хранение состояния диалога, предел журнала версий | BE1 с BE2/BE3 | BE1-03/04, BE2-02/06 |
| Быстрая отметка во время незавершённого диалогового draft | BE2 с BE1 | BE2-05/02, BE1-03; старый draft нельзя молча уничтожить |
| Провайдер/модель, ключ, бюджет и лимит платных прогонов | Руководитель и BE2 | BE2-03/07/08, защищённая конфигурация; не в публичных карточках |
| Диалог уточнения порции, даты/числа; показ нескольких извлечённых показателей | BE2 с BE1/BE3/FE1 | BE2-03/04/06, FE1-04; неизвестное нельзя угадывать |

| Точная раскладка, props общих компонентов, библиотека графиков, display-округление | FE1/FE2 с BE3 по смыслу чисел | FE1-02, FE2-01/02/03; формулы backend не меняются |
| Формат URL-фильтров, возврат из дневника, UX конфликта 409 и старых данных при загрузке | FE1/FE2, BE1 по ответам | FE1-03–05, FE2-04/05 |
| Механизм инвалидирования/защиты гонок и общий браузерный runner | FE1/FE2 | FE1-05/06, FE2-05/06; второй клиент не нужен |

После согласования: записать решение, автора, дату, ссылку на обсуждение/контракт и затронутые задачи. Не переписывать ТЗ односторонне. Если согласованное решение меняет контракт, его проверяют потребители.

Уже заданные требования не являются открытыми: Europe/Warsaw по умолчанию, свежесть initData 15 мин / сессия 60 мин, таймаут модели 30 с, JPEG/PNG 5 MiB / 12 Мп, три периода Сегодня/7/21, четыре категории 1–5 и четыре блока,12 визуальных кейсов,3 профиля по 21 дню, подтверждение модели человеком, owner/revision/повторы и безопасный reset.
